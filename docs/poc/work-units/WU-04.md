## Phạm vi triển khai

1. Xây Button/IconButton, Field/Input/Textarea/PasswordInput base, Checkbox/Toggle, Badge/AvatarBase, Tabs/SegmentedControl, Panel, Progress, Alert/Empty/Skeleton/KeyHint.
2. Controlled props/ref/disabled/error/focus/size variants nhỏ; không domain imports. Giữ select behavior/design bằng headless logic hoặc primitive tự quản trong phạm vi.
3. Tạo harness/gallery cô lập để so primitive states và các biến thể. WU-07 ghép gallery vào AppShell khi shell có thật; WU-28 hoàn thiện hai gallery theo source. Chưa dựng AppShell sớm trong unit này.
4. Gom shared classes/variant definitions trong component; không copy long class strings sang từng page.

## Acceptance criteria

- **WU-04-AC1:** Button có chiều cao 22/26/30/36px; radius, cỡ chữ và spacing khớp source theo từng variant.
- **WU-04-AC2:** Keyboard/focus/disabled/validation semantics hoạt động; consumer không cần DOM enhancer sau render.
- **WU-04-AC3:** Gallery so ảnh đạt các primitive states; packages/ui không biết workspace/task/router.

## Verification bắt buộc

- Visual gallery controls+states; focused keyboard interactions và controlled rerender test.
- Typecheck/build; không snapshot implementation chi tiết thay acceptance.
- Dùng script thực tế của repo; nếu tên script tài liệu chưa tồn tại, tạo/ghi tên tương đương có thật trong phạm vi unit. Ghi command, exit status, artifact và lỗi còn lại. Không ghi “pass” khi chưa chạy.

## Quy trình và điều kiện dừng

Trước khi sửa: inspect implementation + PROGRESS; xác minh prerequisite; đưa kế hoạch ngắn 3–7 bước. Sau đó implement ngay trong session. Không làm unit sau, không refactor ngoài phạm vi, theo convention và chỉ thêm tests cần cho unit.

Trước khi kết thúc: chạy verification, sửa lỗi do work, cập nhật PROGRESS với acceptance/evidence/conflicts/blockers, commit thay đổi thuộc unit, push repo đích `main` đã cấu hình theo AGENTS, báo kết quả bằng tiếng Việt rồi dừng.

Chỉ đánh dấu **DONE** khi mọi AC và gate bắt buộc đạt. Thiếu browser/source baseline/DB binding/quyền push phải báo riêng đúng bước; không bịa kết quả. Code chưa đạt thì **IN_PROGRESS** hoặc **BLOCKED**, không nhảy qua unit tiếp theo.
