## Phạm vi triển khai

1. Hiện thực Zod schemas và inferred DTO/enums/request/response/errors trong packages/contracts; tên operation/path theo API_CONTRACT là canonical.
2. Chốt DateOnly thật, UTC instant, nullable PATCH semantics, UUIDv7 IDs, entity version, typed capability, restricted project DTO, cursor query và full-view completeness.
3. Định nghĩa StudioApi interface với các operations trong contract; tách request input khỏi database rows và HTML presentation.
4. Chuẩn hóa danh mục status/priority/labels/recurrence/template + deterministic ID map cho fixture nguồn, giữ visible task keys/tên/số liệu cần đối chiếu.
5. Tạo contract fixtures success/error/nullable/date/bulk/order và endpoint coverage index. Nếu xuất OpenAPI, generate từ cùng schema hoặc có explicit drift check; không viết hai bộ enum độc lập.

## Acceptance criteria

- **WU-02-AC1:** FE/mock/BE có cùng schema imports; packages/contracts không chứa dependency Hono/Drizzle/React.
- **WU-02-AC2:** Ngày 2026-02-30 bị từ chối; null khác absent; assignee/member/project IDs có semantics rõ.
- **WU-02-AC3:** Operation list đủ cho inventory; dịch vụ external được gắn demo/unavailable, không có success contract giả làm dịch vụ thật.
- **WU-02-AC4:** Request/response contract samples parse được; bulk/order/error/undo không dùng any hoặc Record tự do thay mô hình.

## Verification bắt buộc

- Contract schema tests cho cases nguy hiểm: ngày không hợp lệ, PATCH null, unsupported enum, mutation version, cursor validation.
- Typecheck consumers mẫu; kiểm tra operation coverage theo API_CONTRACT.
- Dùng script thực tế của repo; nếu tên script tài liệu chưa tồn tại, tạo/ghi tên tương đương có thật trong phạm vi unit. Ghi command, exit status, artifact và lỗi còn lại. Không ghi “pass” khi chưa chạy.

## Không thuộc unit này

Chưa implement toàn bộ mock hay endpoints; chưa Drizzle migrations.

## Quy trình và điều kiện dừng

Trước khi sửa: inspect implementation + PROGRESS; xác minh prerequisite; đưa kế hoạch ngắn 3–7 bước. Sau đó implement ngay trong session. Không làm unit sau, không refactor ngoài phạm vi, theo convention và chỉ thêm tests cần cho unit.

Trước khi kết thúc: chạy verification, sửa lỗi do work, cập nhật PROGRESS với acceptance/evidence/conflicts/blockers, commit thay đổi thuộc unit, push repo đích `main` đã cấu hình theo AGENTS, báo kết quả bằng tiếng Việt rồi dừng.

Chỉ đánh dấu **DONE** khi mọi AC và gate bắt buộc đạt. Thiếu browser/source baseline/DB binding/quyền push phải báo riêng đúng bước; không bịa kết quả. Code chưa đạt thì **IN_PROGRESS** hoặc **BLOCKED**, không nhảy qua unit tiếp theo.
