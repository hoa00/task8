## Phạm vi triển khai

1. Hiện thực tasks query/detail/create/patch/move/bulk/duplicate/archive/delete/restore/favorite theo contract. Tạo task dùng clientRequestId và request hash để retry không tạo trùng; response có entity version và các projection bị ảnh hưởng.
2. Giữ filter/sort/date/null semantics đã chốt; cursor ổn định, totals trên toàn authorized scope. Bulk giới hạn số item và bound parameters đúng D1.
3. Move nhận neighbor IDs/scope/patch có kiểu; server tự tính thứ tự và kiểm tra quyền. Project move cấp key hợp lệ; Calendar/Timeline dùng chung reschedule PATCH.
4. setTaskCompletion dùng endpoint completion riêng, phân biệt với PATCH status và bulk field edit. Complete/reopen/recurrence cùng canonical rules giữa mock và HTTP; monthly theo tháng lịch là correction trong DECISIONS. Column complete/archive dùng ColumnScope và exact ID/version set theo contract, không lấy riêng page đã tải hoặc toolbar filter làm toàn column.
5. Mở rộng undoCommand với task/bulk/column kinds; version guard, task writes, activity, bounded inverse record và one-shot consumption có atomicity đúng DATA_MODEL. Single recurring completion Undo giữ successor như source; column inverse kiểm tra successor/child state để không xóa thay đổi mới. SQL update 0 row phải thành conflict, không được xem như batch tự rollback vì SQL vẫn thành công.
6. Hiện thực sanitizer chạy trong Worker, canonical descriptionHtml/descriptionText và các helper scope/label/dependency/subtask validation cho mọi field mà create/PATCH nhận. Nếu endpoint đã nhận input thì invariant phải có ở unit này; không trì hoãn validation tới WU-33. WU-33 dùng lại các helper để mở rộng nested endpoints.

## Acceptance criteria

- **WU-32-AC1:** Concurrent task creation không trùng key; assignee/project/neighbor khác workspace bị từ chối.
- **WU-32-AC2:** Bulk có một thay đổi không hợp lệ không để lại partial writes hoặc phantom activity.
- **WU-32-AC3:** Null/absent/date-only/complete/reopen/recurrence và Undo conflict đúng contract; caller không tự set version/actor/timestamps hoặc gửi inverse snapshot tùy ý.
- **WU-32-AC4:** Retry cùng create clientRequestId trả cùng task; payload khác cho request ID đã dùng bị từ chối. Retry Undo không áp inverse hai lần; một conflict trong bulk/column inverse không ghi partial effects.
- **WU-32-AC5:** Task create/PATCH sanitize content và kiểm tra quan hệ ngay tại server; source format được giữ theo allowlist, cross-workspace/self/cycle input bị xử lý đúng contract. Không dùng regex-only sanitizer.

## Verification bắt buộc

- Local D1 tests cho concurrent key allocation, idempotent create, reorder conflicts, bulk rollback, delete/restore, one-shot Undo và Undo sau edit mới.
- Task query/schema fixtures khớp mock; typecheck/build liên quan.
- Worker content payload và relation-validation cases cho fields đã có trong create/PATCH; không chỉ test helper trong Node.
- Ghi lệnh thực tế, exit status và evidence path; test không chạy không được báo pass.

## Quy trình và điều kiện dừng

Trước khi sửa: inspect implementation + PROGRESS; xác minh prerequisite; đưa kế hoạch ngắn 3–7 bước. Sau đó implement ngay trong session. Không làm unit sau, không refactor ngoài phạm vi, theo convention và chỉ thêm tests cần cho unit.

Trước khi kết thúc: chạy verification, sửa lỗi do work, cập nhật PROGRESS với acceptance/evidence/conflicts/blockers, commit thay đổi thuộc unit, push repo đích `main` đã cấu hình theo AGENTS, báo kết quả bằng tiếng Việt rồi dừng.

Chỉ đánh dấu **DONE** khi mọi AC và gate bắt buộc đạt. Thiếu browser/source baseline/DB binding/quyền push phải báo riêng đúng bước; không bịa kết quả. Code chưa đạt thì **IN_PROGRESS** hoặc **BLOCKED**, không nhảy qua unit tiếp theo.
