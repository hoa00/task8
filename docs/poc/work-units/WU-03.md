## Phạm vi triển khai

1. Dùng Tailwind ngay từ đầu; explicit theme/utilities imports và normalized base faithful. Không import toàn bộ CSS legacy hoặc copy .btn/.taskrow như stylesheet chính.
2. Ánh xạ nguyên giá trị light/dark/accent/spacing/type/radius/sizes qua CSS custom properties và @theme inline; kiểm tra font weights 450 với descriptors nguồn.
3. Self-host/replay đúng font bytes/descriptors đã lock, icon paths đúng source lucide lock và stroke1.8; custom status/priority glyphs không thay icon gần giống.
4. Tạo ThemeProvider/prefs-to-root attributes; system/light/dark, accent, comfortable/compact, motion; không mirror business data.
5. Định nghĩa breakpoint variants inclusive <=1100/900/640 và hover behavior theo source, keyframes/scrollbar CSS allowlist.

## Acceptance criteria

- **WU-03-AC1:** Font tải thật và computed style/token đúng source; không dùng font fallback làm pass.
- **WU-03-AC2:** Color/typography/geometry primitive sample khớp reference; tất cả 6 accent, light/dark và density switch cập nhật đúng.
- **WU-03-AC3:** Build scan classes qua packages/ui hoạt động; không dynamic string class không được Tailwind detect.

## Verification bắt buộc

- So sánh token/icon/type sample với reference trong cùng runner.
- Probe breakpoint boundaries và system theme/motion; typecheck/build.
- Dùng script thực tế của repo; nếu tên script tài liệu chưa tồn tại, tạo/ghi tên tương đương có thật trong phạm vi unit. Ghi command, exit status, artifact và lỗi còn lại. Không ghi “pass” khi chưa chạy.

## Quy trình và điều kiện dừng

Trước khi sửa: inspect implementation + PROGRESS; xác minh prerequisite; đưa kế hoạch ngắn 3–7 bước. Sau đó implement ngay trong session. Không làm unit sau, không refactor ngoài phạm vi, theo convention và chỉ thêm tests cần cho unit.

Trước khi kết thúc: chạy verification, sửa lỗi do work, cập nhật PROGRESS với acceptance/evidence/conflicts/blockers, commit thay đổi thuộc unit, push repo đích `main` đã cấu hình theo AGENTS, báo kết quả bằng tiếng Việt rồi dừng.

Chỉ đánh dấu **DONE** khi mọi AC và gate bắt buộc đạt. Thiếu browser/source baseline/DB binding/quyền push phải báo riêng đúng bước; không bịa kết quả. Code chưa đạt thì **IN_PROGRESS** hoặc **BLOCKED**, không nhảy qua unit tiếp theo.
