## Phạm vi triển khai

1. Hiện thực upload multipart tối thiểu và content download qua Hono tới R2 local; D1 giữ metadata có workspace/project/task scope theo contract.
2. Xử lý failure giữa R2 và D1 bằng state/compensation có phạm vi: hai dịch vụ không có chung transaction. Không đánh dấu file ready khi object hoặc metadata chưa hoàn tất.
3. Validate size/type/quyền, không lưu file bytes/base64 trong D1. Sample files giữ asset provenance và screenshot fixture riêng.
4. Nối HTTP upload/content operations; progress đo byte thực hoặc dùng trạng thái không xác định nếu transport không đo được. Upload hoàn thành phải chờ server response, không chỉ timer.
5. FileCard/AttachmentCard tiếp tục là component đã làm; preview nội dung mới chỉ cho loại hỗ trợ, các loại khác dùng fallback thiết kế nguồn.
6. Mỗi draft upload có clientRequestId ổn định và kiểm tra payload/hash theo contract. TaskForm tạo task một lần rồi upload từng file theo taskId đã nhận; retry file lỗi không POST tạo task lại, không reset failed draft khi Create more chưa hoàn tất toàn lượt submit.

## Acceptance criteria

- **WU-35-AC1:** Upload bytes thật rồi download có checksum trùng; cùng file hiện ở Project Files và TaskDrawer, rename/delete phản chiếu đúng.
- **WU-35-AC2:** Content endpoint enforce access; failure tại R2 hoặc D1 không tạo phantom ready file và có cách retry/cleanup rõ.
- **WU-35-AC3:** Không đổi component khi chuyển mock/HTTP; capability cap/progress/error state theo API.
- **WU-35-AC4:** Retry sau mất response không tạo thêm task/file đã xác nhận; không cleanup object của winning row. Kết quả commit chưa rõ phải giữ object/intent để kiểm chứng và retry, ghi nhận phần chưa giải quyết thay vì hứa không có orphan tạm thời. Task đã tạo nhưng attachment fail có trạng thái partial rõ, giữ draft và không báo toàn bộ thành công.

## Verification bắt buộc

- Wrangler local R2 + D1 tests cho bytes checksum, metadata/object linkage và simulated failures.
- UI upload/download/reload và fixture visual; typecheck/build.
- TaskForm create kèm nhiều draft files, lỗi một upload, retry cùng request ID và payload mismatch; kiểm tra task/file identity không nhân đôi.
- Phân biệt SQL rollback đã xác nhận với mất D1 acknowledgement sau commit; kiểm tra nhánh chưa xác định không xóa bytes của committed file, retry resolve đúng identity và cleanup chỉ confirmed losing object.
- Ghi lệnh thực tế, exit status và evidence path; test không chạy không được báo pass.
