## Phạm vi triển khai

1. Chọn HTTP adapter ở bootstrap; Vite proxy /api tới Worker dev. Giữ các feature component/data hooks đã thiết kế, không viết page-specific fetch.
2. Chạy journey workspace/project/task/subtask/comment qua List/Board/Table/Calendar/Timeline, upload/download tệp, reload và archive/undo trên D1/R2 thật.
3. Kiểm tra workspace/private access, 403/404/409, bulk rollback, mất mạng, giữ draft, hủy response cũ khi chuyển workspace.
4. Chạy ma trận visual đã thống nhất với cùng fixture/state. Mọi sửa khác behavior nguồn phải trỏ đến dòng DECISIONS cụ thể; không dùng ngoại lệ để bỏ qua lỗi hình thức.
5. Hoàn tất README lệnh thực tế, PROGRESS và acceptance report; ghi rõ các external capabilities còn unavailable, không tuyên bố đã deploy production.

## Quy trình và điều kiện dừng

Trước khi sửa: inspect implementation + PROGRESS; xác minh prerequisite; đưa kế hoạch ngắn 3–7 bước. Sau đó implement ngay trong session. Không làm unit sau, không refactor ngoài phạm vi, theo convention và chỉ thêm tests cần cho unit.

Trước khi kết thúc: chạy verification, sửa lỗi do work, cập nhật PROGRESS với acceptance/evidence/conflicts/blockers, commit thay đổi thuộc unit, push repo đích `main` đã cấu hình theo AGENTS, báo kết quả bằng tiếng Việt rồi dừng.

Chỉ đánh dấu **DONE** khi mọi AC và gate bắt buộc đạt. Thiếu browser/source baseline/DB binding/quyền push phải báo riêng đúng bước; không bịa kết quả. Code chưa đạt thì **IN_PROGRESS** hoặc **BLOCKED**, không nhảy qua unit tiếp theo.
