## Actual installed-runtime incompatibilities

Probe uses actual Wrangler `4.148.0`, current Worker app, `RequestRepository` and local D1. Unicode samples satisfy `NameSchema`; tuple IDs satisfy `EntityIdSchema`. All SQL is readonly on a virtual bound JSON dataset in isolated test storage. Test hook is absent from production (404). This is a capability probe, **not** endpoint/privacy/count/EXPLAIN acceptance.

- `BINARY` name order differs from Workerd `localeCompare` (`en-US`, sensitivity variant, numeric false, ignorePunctuation false). `NOCASE` also differs, including accent/canonical-equivalence ordering. Project/member/file name paging would change page membership and continuation.
- Task relational UTF-16 comparison puts U+10000 before U+E000; SQLite UTF-8 BINARY puts U+E000 first. This affects title/assignee/project text sorts and seek predicates.
- JavaScript folds `Änne`→`änne`, `Kelvin`→`kelvin`, `İSTANBUL`→`i`+U+0307+`stanbul`; SQLite `lower()` leaves these initial characters unchanged. q/type/title filters and counts can disagree with the existing domain/mock/server behavior.
- `%_` is literal under `.includes`; `LIKE '%…%'` instead matches `AXB`. `instr` avoids wildcard semantics, but still requires canonical Unicode-folded stored text.
- `icu_load_collation` is unavailable (`no such function`). D1 forbids `sqlite_version()` and `PRAGMA collation_list` in this binding; no SQLite version or collation inventory is claimed. Workerd locale/options and actual query results are retained in evidence.

Current cursor v1 preserves sortValue as the original string/number/null. An anchor can disappear/rename. A rank computed over current names cannot locate an arbitrary old tuple without loading/comparing the catalogue again; this would be the prohibited full-load fallback. More indexes alone do not resolve comparator semantics.

## Compatibility-preserving design — approved by Hòa

1. Establish an explicit versioned text semantics specification before migration: locale/options and ICU/Unicode data version. Existing qualified Workerd resolves en-US, but default locale/ICU can differ across browser/mock/runtime. Pinning it needs a documented decision and differential checks; do not silently change ordering in a structural refactor.
2. Provide a deterministic sort-key encoder compatible with that specification for every Unicode string, executable in Worker and shared consumers. JavaScript Intl exposes compare, not sort keys; D1 cannot install this collation. Evaluate a pinned Worker-compatible ICU/UCA encoder against current Intl, including composed/decomposed accents, supplementary characters, case, punctuation and mixed scripts. A release-compatible encoder is a prerequisite, not an assumed implementation.
3. Keep task text comparison distinct: encode raw JS UTF-16 code units as fixed-width ASCII hex (case folding only for title). It reproduces `<`/`>` lexicographic ordering without SQLite UTF-8 differences. Preserve primary direction and ID ascending, null behavior and existing sentinels.
4. Store JS-folded search text and computed sort keys with explicit encoding version. Use `instr(storedFold, boundJsFoldedQuery)>0` for literal q; never SQLite `lower/NOCASE/LIKE` as a substitute. Generated task key matching, member email/title and project catalog description require the same defined folding. Join lookup keys through their owners for task assignee/project sorts.
5. Add a separate forward migration with ledger preservation, bounded backfill, detection of mismatched key versions, and indexes established from representative EXPLAIN/rows_read. All owning create/update/duplicate/profile/membership/name paths write the derived values in their existing guarded native batch. Fixtures/historical migrations/ID map stay immutable; active seed/backfill uses the new versioned encoder.
6. Encode the old cursor sortValue at request time with the same encoder for seek; do not require anchor lookup. Keep v1 schema/query fingerprint/tie direction if exact old semantics are retained. If key format or canonical comparator requires a cursor version change, document migration/consumer implications before implementation; reject neither old valid tuples nor renamed anchors silently.
7. Compile finite filter/sort expressions and separate page LIMIT+1 from full-scope count/summary. Share authorized/lifecycle predicates; keep comments/activity/notification own tie direction. Command full-set reads remain separate. Gate with multi-page/tie/null/date/literal/Unicode/removed-anchor/privacy equality, two workspaces and actual D1 EXPLAIN/rows metrics. Then proceed BR-07B and BR-08/root audit.

## Alternative requiring a behavior decision

Adopt explicit deterministic UTF-16 or another documented comparator for project/member/file text across backend/domain/mock/UI, then persist matching keys. This simplifies Worker/D1 parity, but changes existing `localeCompare` ordering (`a/ä/B/z` vs binary order), page contents and cursor behavior. It exceeds this plan's preservation constraint without an explicit contract decision. No implementation or migration for this alternative has been applied.

## Remaining gates

Compiler, migration/backfill/encoder compatibility, endpoint traversal/summary/privacy parity, EXPLAIN/rows proofs: **NOT_RUN**, because the text semantics/encoder prerequisite is unresolved. Production still runs the explicitly documented legacy full-load reads; they are not an acceptance fallback. BR-07A is not DONE; BR-07B and BR-08 remain NOT_STARTED by their prerequisites.

## Implemented compatibility specification

- ICU4C78.2 at Chromium revision `6ebb40c594776cc2c21ea14df85a2a89a328b364`, matching qualified Workerd1.20261006.1/V8 15.5.35.7. en-US, variant/tertiary, numeric off, caseFirst off, punctuation significant, normalization on. Exact Chromium packaged root/en/en_US/implicit-Han collation data is embedded. Node seed/backfill and Worker use the same 667543-byte Wasm; [provenance/build/Unicode license](../../apps/api/tooling/collation/README.md).
- Native corpus10029 includes canonical-equivalent accents, Vietnamese, mixed scripts, supplementary characters, punctuation, case and lone UTF16 surrogates. Locale-key D1 ordering, UTF16 ordering and ICU root lowercase match Workerd Intl/String semantics. SQL fixed-position date keys match162 dates spanning years0001…9999. Canonical history cursors seek indexed epoch values; arbitrary old string tuples use exact ICU-key comparison without an anchor lookup.
- Cursor encoding keeps original string/number/null and v1 bindings. Task keys preserve relational UTF16 and JavaScript mixed numeric/string/null/NaN/Infinity comparisons. History primary and ID directions remain distinct from task/project/file/member ties. Canonical stored UUIDs are lowercase; uppercase cursor IDs retain ICU tertiary continuation through the locale-ID seek helper.
- D1 writes lone surrogates as WTF8 and its JS read decoder returns three U+FFFD characters per surrogate. Native echo confirms both bound values and json_extract. Derived fields encode that read projection; cursor encoder retains the original UTF16 units. Bounded backfill CAS compares hex(source bytes), preserving existing invalid UTF8 without mistaking decoder replacement for source mutation.
- `readKeys` JSON includes a version and owned full/partial text fields. Task/project/file/comment/profile writes maintain keys in their existing guarded native batch, including template/copy/recurrence/promotion. Partial patches do not set the complete version on legacy records. Missing versions fail an affected read explicitly, without a hidden full-load fallback or a truncated successful count.
- Forward migration0001 adds derived columns only. Migration0002 adds reviewed scoped indexes. Native old-ledger upgrade and bounded40-row backfill/rerun preserve all23 tables, identity/version/timestamps/history and the old ledger prefix. Existing migrations, source fixture and ID map remain unchanged.
